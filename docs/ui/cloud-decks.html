⑥ 从其他词表导入只动「挂载关系」：把对方的词挂到我这表上，不复制词条本身。替换 / 追加二选一。

1数据结构要加三个字段

  • decks.visibility —— private / public；官方仍用 owner_id IS NULL 判定，不混进可见性。
  • decks.share_code —— 8 位，唯一索引；为空表示还没生成过。
  • decks.source_deck_id —— fork 来源，用于「复制自《考研5500》」这种标注，可空。

2接口增减

  • GET /api/decks?scope=all|official|public|mine&q= —— 一次拿完，带 shareCode、owner、wordCount、alreadyLocal。
  • GET /api/decks/by-code/{code} —— 分享码直达。
  • PATCH /api/decks/{id} —— 放开 description + visibility。
  • POST /api/decks/{id}/share-code/reset、POST /api/decks/{id}/import-from（sourceId + mode=replace|append）。
  • POST /api/decks 增加 seedFromDeckId、visibility。

3分享码规则

8 位 Crockford Base32（去掉 I L O U，避免 1/l、0/O 认错），显示成 XXXX-XXXX。 生成时排除已用的码；重置后旧码立刻失效。公开词表才有码，改回私有时代码保留但不可用。

4权限边界不变

官方词表：所有人读，仅管理员写。公开词表：任何登录用户可读、可下载、可复制，不能改。 私有词表：仅本人。别人的私有表依旧返回 404。上传 CSV 仍只写自己的 user_words。

5要你拍板的三件事

  • 公开词表要不要允许未登录访问分享码？ —— 目前所有词表接口都要令牌，我倾向保持「必须登录」，分享码只解决"找不到"的问题。
  • 「从其他词表导入」是复制词条还是只挂载？ —— 设计稿按只挂载画（省空间，对方的词更新我这边跟着变）；如果你希望"独立一份、各自改"，那就改成复制到 user_words。
  • 分享码能不能自定义？ —— 比如给自己这张表起个 WRITING-01。可以，但要额外校验唯一性与敏感词。
